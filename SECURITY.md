# Security Policy

## Supported Versions

The latest build of Flax is always the recommended place to start should you have
an issue.  Older versions, especially betas, do not contain the functionality of
the latest release, and retrofitting fixes into beta or release candidate builds
is not possible.

Once past the release candidate stage and the system is feature complete, then
official release builds will be maintained where applicable.

## Reporting a Vulnerability

If a security issue is found, it will be fixed and addressed in the latest release.
During development, it is not possible to retrofit fixes and changes in betas or 
release candidates.  As Flax is a constantly evolving language, early release builds
will in most cases not contain the full feature set of an official release.

Please log any issues through the issue tracking system.
